# Constraining the Language Model: A Schema-Validated Framework for Automated Structured Reporting of Intracranial EEG in Presurgical Epilepsy Evaluation


**Authors:** Azhar Saparova, Berdakh Abibullaev

Research code and reproducibility materials for the study:

**“Constraining the Language Model: A Schema-Validated Framework for Automated Structured Reporting of Intracranial EEG in Presurgical Epilepsy Evaluation.”**

---

## Project Summary

This repository contains the code, notebooks, model checkpoint, documentation, and selected derived results for a research project on automated analysis and structured reporting of intracranial EEG (iEEG) data for presurgical epilepsy evaluation.

The project develops a multi-stage pipeline combining:

1. high-frequency oscillation (HFO) analysis;

2. seizure detection;

3. structured integration of electrophysiological evidence;

4. schema-constrained LLM reasoning;

5. deterministic validation and report generation.

The LLM does not analyze raw iEEG recordings directly. Instead, it operates on structured summaries generated by the signal-processing and seizure-detection components. The framework constrains model outputs using predefined schemas and validation rules before producing the final human-readable report.

## Methodology Overview

## 1. HFO Detection Branch

The HFO branch focuses on detecting high-frequency oscillation evidence from iEEG recordings.

Main components:

- initial experiments on OpenNeuro ds003498;
- HUP dataset adaptation;
- ripple detection;
- fast ripple detection;
- FRandR analysis;
- HFO area estimation using high-rate channels;
- export of structured HFO JSON summaries.

Expected LLM input produced by this branch:

```text
sub-HUPXXX_hfo_subject_summary_for_llm.json
```

---

## 2. Seizure Detection Branch

The seizure branch focuses on seizure-event detection from HUP iEEG recordings.

Main components:

- initial seizure detection experiments on SWEC-ETHZ;
- HUP preprocessing;
- window-based segmentation;
- CNN-transformer-based seizure detection;
- evaluation at run and subject levels;
- export of structured seizure JSON summaries.

Expected LLM inputs produced by this branch:

```text
sub-HUPXXX_*task-ictal*_seizure_summary_for_llm.json
sub-HUPXXX_*task-interictal*_seizure_summary_for_llm.json
```

---

## 3. LLM Reporting Branch

The LLM branch receives structured JSON summaries from the HFO and seizure branches.

The LLM system uses these structured inputs to:

- build a subject-level master case;
- create a compact LLM-ready case;
- reason over HFO and seizure evidence;
- compare cross-modal agreement or mismatch;
- produce validated reasoning JSON;
- generate a structured iEEG report;
- in Version 4, perform bounded tool orchestration.

Expected final outputs include:

```text
integration/
  *_master_case.json
  *_compact_case.json

reasoning/
  *_reasoning_raw.txt
  *_reasoning_validated.json
  *_reasoning_validation_report.json

reports/
  *_final_report.md
  *_final_report.txt

orchestration/
  *_tool_plan_validated.json
  *_tool_execution_log.json
```

## Reproducing Results

The project can be reproduced at three levels.

### Level 1: LLM Report Reproduction

This is the easiest and most reliable level.

It uses already prepared HFO and seizure JSON summaries.

Steps:

1. Install Python dependencies.
2. Install and run Ollama.
3. Go to the required LLM version folder.
4. Run the LLM pipeline.
5. Inspect generated reasoning and report outputs.

Example:

```bash
cd src/llm/version_4

python run_pipeline.py \
  --project-root . \
  --subject-id sub-HUP146 \
  --model-name qwen3:8b \
  --ollama-url http://127.0.0.1:11434/api/generate
```

For Version 4 orchestration:

```bash
python run_orchestration.py \
  --project-root . \
  --subject-id sub-HUP146 \
  --model-name qwen3:8b \
  --ollama-url http://127.0.0.1:11434/api/generate
```

---

### Level 2: JSON Summary Reproduction

This level requires processed outputs from the HFO and seizure branches.

Steps:

1. Run HFO preprocessing.
2. Run HFO detection and FRandR analysis.
3. Export HFO summary JSON.
4. Run seizure preprocessing.
5. Run seizure detection/evaluation.
6. Export seizure summary JSON files.
7. Copy JSON summaries into the relevant LLM subject folder.
8. Run the LLM reporting pipeline.

---

### Level 3: Full Reproduction from Raw Data

This level requires access to the original datasets.

Steps:

1. Download or obtain access to OpenNeuro ds003498, SWEC-ETHZ, and HUP datasets.
2. Place raw data according to `data/README.md`.
3. Run preprocessing notebooks.
4. Run HFO detection.
5. Run seizure detection.
6. Generate structured JSON summaries.
7. Run LLM reporting.
8. Compare generated results with the reference outputs included in the repository.

See detailed instructions:

```text
docs/reproduction_guide.md
```
